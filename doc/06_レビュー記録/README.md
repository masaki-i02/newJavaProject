# 06_レビュー記録

設計書と実装のレビューで挙がった指摘と、その対応を記録する。

## なぜ残すか

**指摘そのものより、どう判断したかに価値がある。**
「この指摘は受け入れて設計を変えた」「この指摘は認識したうえで今回は対応しない」という
判断の記録が無いと、同じ議論が繰り返される。

対応した結果は設計書と ADR に反映されるが、
**なぜその変更が必要になったのか（どんな欠陥に気づいたのか）はここにしか残らない。**

## 記録の方針

- 1 回のレビューにつき 1 ファイル
- 指摘は重大度（高 / 中 / 低）と対応状況を持つ
- 「対応しない」と判断したものも、理由とともに残す
- 設計書を改訂したら、設計書側の改訂履歴からこの記録を参照する
- **レビュアーには「実際に手を動かして裏付けを取る」ことを課す。**
  推測の指摘は数だけ増えて判断できない。第 3 回では乱数ファザ・
  ミューテーション・実 DB への INSERT・生成物の再生成で裏付けを取った
