## 1. なぜ 3 本に分けたか

同じ人（同じ文脈）が続けて見ると、**直したばかりの箇所を正しいものとして読む。**
①は「サーバが実際に何を返すか」を実物に当てて調べ、
②は「新しく開けた口から何が入るか」を実物に当てて調べ、
③は「直したつもりの欠陥を、テストが本当に捕まえるか」を
**修正を 1 つずつ元へ戻して**調べた。

**コードを読んだだけの指摘は採らない**と決めた（落とし穴 11）。

## 2. 指摘と対応

### 2.1 手書きの TS 型とサーバ応答（レビュー ①）

| # | 指摘 | 対応 |
| --- | --- | --- |
| 1 | **`DailyAttendance.overtimeMinutes` はサーバに存在しない。** 日次の時間外は法定内・法定外の 2 列である | 型を 2 列に直し、画面も 2 列にした。**1 列に束ねない**（割増 0% と 25% で支払う賃金が違う。落とし穴 115）|
| 2 | `WallClockDateTime` は小数秒を拒否する正規表現なのに、サーバは `…T03:49:10.534283` を返す | サーバ側を秒までにそろえた（下記 2.4）|
| 3 | `Approver.employeeId` は省略ではなく `null` が来る | 型を `string \| null` にした |
| 4 | `Warning.dates` は必ず来るのに省略可能と宣言していた | 必須にし、画面の恒真の分岐を消した |
| 5 | `<input type="month">` は値を消せるので `asYearMonth('')` が例外になる | 空なら月を変えない |
| 6 | **詳細を開いたまま月を切り替えると、表示している月と違う月を決裁する** | 決裁の URL を `selected.month` から作り、月が変わったら詳細を閉じる |

`overtimeMinutes` は**画面が落ちない**種類の欠陥だった。
`Math.floor(undefined / 60)` は例外ではなく `NaN` を返すので、
「時間外」列に `NaN:NaN` と出るだけである。
**落とし穴 127 と同型だが、こちらのほうが気づきにくい。**

### 2.3 テストの実効性（レビュー ③）

修正を 1 つずつ元へ戻し、該当するテストが落ちるかを確かめた。

| 変異 | 結果 |
| --- | --- |
| `SessionController` の分岐を `changeSessionId()` だけに | `IT-AUTH-18` が 500 で落ちた |
| `handleMissingParameter` を削除 | `IT-API-13` が落ちた（**`$.type` が殺した。** ステータスだけなら Spring の既定が 400 を立てるので生き残る）|
| `handleTypeMismatch` を削除 | `IT-API-14`・`15` が 500 で落ちた |
| `handleNoResource` を削除 | `IT-API-16` が落ちた |
| `MAX_PERIOD_DAYS` を 366 → 3660 | `IT-API-18` が落ちた（境界の両側を押さえている）|
| 期間の逆転検査を無効化 | `IT-API-17` が 500 で落ちた |
| `Totals.of` の `baseMinutes` を 0 に | `IT-API-32` が落ちた |
| **`dispatcherTypeMatchers(ERROR).permitAll()` を削除** | **1 件も落ちなかった** |

最後の 1 件だけが生き残った。レビュー ③ は
「この行は等価変異であり、効いているのは例外ハンドラだけだ」と結論した。

**この結論は、確かめた範囲が狭かった。**
自分で実測し直したところ、この行が守っているのは
**`@ExceptionHandler` が拾えない失敗**だった。

| 要求 | 行あり | 行なし |
| --- | --- | --- |
| 必須パラメータの欠落・URL の綴り誤り・型の不一致 | 400 / 404 + 本文 | **同じ**（ハンドラが直接ステータスを立てるので ERROR 転送に入らない）|
| `StrictHttpFirewall` の拒否（`/api/%2e%2e/me`）| 400 + 本文 | **403・本文なし** |
| 406 Not Acceptable | 406 | **403・本文なし** |

前者しか試していなかったので等価に見えた。
**`IT-OPS-12` を足して殺せることを確認した**（実コンテナ。MockMvc は ERROR 転送を再現しない）。
`SecurityConfig` のコメントも、実測した内容に書き換えた
（コメントがルールより強いことを言わない。落とし穴 85）。

### 2.4 日時の桁（①の 2 番から）

打刻は `Clock` から（ナノ秒）、証跡は DB の `now()` から（マイクロ秒）来る。
**出どころが 2 つあるので、変換の側で 1 か所にそろえた**（`JsonConfig`）。

`toString()` には任せない。秒が 0 のとき秒そのものを省くので、
`09:00:00` が `09:00` になり**桁数が値によって変わる**（IT-API-35）。

**履歴を読んでも気づけない。**
