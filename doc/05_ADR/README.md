# 05_ADR（Architecture Decision Record）

設計上の判断と、その理由を記録する。

## なぜ書くか

コードを読めば「何をしているか」は分かるが、「なぜ他の選択肢を採らなかったか」は分からない。
ADR はその差分を埋めるためにある。半年後の自分と、このリポジトリを読む他人のための文書。

## 書き方

- 1 判断 1 ファイル。連番 + 内容が分かる名前（例：`0001_ドメインモデルをrecordで表現する.md`）
- [テンプレート](0000_テンプレート.md) をコピーして使う
- **一度採用した ADR は書き換えない。** 判断が変わったら新しい ADR を書き、
  古いものはステータスを「棄却」にして、後継の ADR へのリンクを追記する
- 「検討したが採らなかった案」を必ず書く。ここが ADR の価値の中心
