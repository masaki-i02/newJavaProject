# ADR 0007: 給与連携を新しい業務コンテキストにする

- **ステータス**: 採用
- **日付**: 2026-09-06
- **関連**: 要件定義書 BR-18 / [給与連携 ドメインモデル設計書](../02_詳細設計/07_給与連携/ドメインモデル設計書.md) / [ADR 0001](0001_パッケージを業務コンテキスト優先で分割する.md) / [設計規約チェックリスト 3](../02_詳細設計/00_共通/設計規約チェックリスト.md)

## 背景

BR-18 は「締めた月次勤怠を、給与計算システムが読める CSV として出力する」ことを求める。
出力する 1 行は **4 つのコンテキストの値を束ねたもの**である。

| 値 | 持っているコンテキスト |
| --- | --- |
| 社員番号・在籍期間 | `employee` |
| 労働時間・不足時間・年休日数 | `attendance` |
| 締め状態・月次勤怠の状態（除外の理由） | `approval` |
| 所定労働日数 | `workrule`（`attendance` 経由）|

新しいコンテキストを増やすのは安くない。
[アーキテクチャ設計書 8](../02_詳細設計/00_共通/アーキテクチャ設計書.md) の AR-10 は
`shared` からの参照を禁じており、**コンテキストを増やすたびに禁止先と違反クラスを足す**
必要がある（落とし穴 84・86）。増やさずに済むなら増やさないほうがよい。

## 検討した選択肢

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A | `attendance` に置く（月次清算の隣） | 値の大半が `attendance` にある。コンテキストが増えない | **04 が決めた「社員番号・氏名・部署を返さない」を破る。** 出力の 1 行は社員番号で始まる。`attendance → employee` の辺は図にあるので参照はできるが、応答に混ぜないという規約のほうを破る |
| B | `approval` に置く（締めの隣） | 「締め済みだけを出す」という条件の持ち主に近い | 労働時間の内訳を `approval` が扱うことになる。締めの状態機械と CSV の列定義が同じパッケージに同居する |
| C | **新しいコンテキスト `payroll` を作る** | 4 つのコンテキストの値を束ねる役目が、どこにも寄生しない。どこからも参照されない末端なので循環が生じない | AR-10 の禁止先と違反クラスが 1 つ増える。パッケージが 1 つ増える |

## 決定

**C を採る。**

決め手は A の欠点である。
[設計規約チェックリスト 3](../02_詳細設計/00_共通/設計規約チェックリスト.md) の
「他コンテキストが所有する概念を返さない」は、
`attendance` の月次清算 API が社員番号を返さないという形で既に守られている。
給与連携を `attendance` に置くと、**同じパッケージの中で守る API と破る API が並ぶ。**
規約は「どちらでもよい」に退化する。

`payroll` は**依存が外へ出るだけ**のコンテキストである。

```
payroll ──→ attendance / employee / approval / shared
```

誰も `payroll` を参照しないので、`shared` にポートを置く必要も生じない
（[ADR 0004](0004_逆向きの問い合わせはsharedにポートを置く.md) の形にならない）。

## 帰結

| 良いこと | 悪いこと |
| --- | --- |
| 「給与へ何を渡すか」を 1 か所で読める | コンテキストが 1 つ増える |
| `attendance` は労働時間の集計だけを持ち続ける | AR-10 の禁止先と違反クラス（`SharedReachesIntoPayroll`）を足す必要がある |
| 出力の記録（`payroll_exports`）の置き場が自明になる | 月次清算の値を読むだけの薄い層になる。**薄いことを理由に `attendance` へ畳みたくなる**が、畳むと上の欠点が戻る |

**計算式を `payroll` に持たせない。**
所定内労働時間（⑨）は不足時間の定義に依存しており、
不足時間の定義を持っているのは `attendance` である。
`MonthlySettlement` の導出メソッドとして `attendance` に置き、`payroll` は呼ぶだけにする。
写すと、制度ごとの数え方を直したときに片方だけが古くなる（落とし穴 67）。
