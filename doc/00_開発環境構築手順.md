# 開発環境構築手順

Eclipse を用いた開発環境の構築と、Git によるバージョン管理の運用をまとめる。

---

## 1. 前提ソフトウェア

| ソフトウェア | バージョン | 備考 |
| --- | --- | --- |
| JDK | 21 | Temurin (Adoptium) を推奨 |
| Eclipse IDE | 2024-03 以降 | **Eclipse IDE for Enterprise Java and Web Developers** を選ぶ（Gradle 連携の Buildship が同梱される） |
| Docker Desktop | 最新 | PostgreSQL の起動に使用 |
| Node.js | 22 | フロントエンド用。バックエンドのみ触る間は不要 |
| Git | 2.40 以降 | Eclipse 同梱の EGit でも可 |

```bash
java -version
# openjdk version "21.x.x" と表示されること
```

## 3. Eclipse の共通設定

プロジェクトを作る前に済ませておく。**特に文字コードは後から変えると既存ファイルが文字化けする。**

### 3.1 文字コードと改行コード

`Window` → `Preferences` → `General` → `Workspace`

| 項目 | 設定値 | 理由 |
| --- | --- | --- |
| Text file encoding | Other → **UTF-8** | ソースにも設計文書にも日本語を含むため |
| New text file line delimiter | Other → **Unix** | `.editorconfig` および CI の実行環境（Linux）に合わせる |

### 3.2 JDK 21 の登録

`Window` → `Preferences` → `Java` → `Installed JREs`

1. `Add...` → `Standard VM` → `Next`
2. `JRE home` に JDK 21 のインストールディレクトリを指定
3. 追加された JDK 21 のチェックボックスを **オン**（既定の JRE にする）

`Window` → `Preferences` → `Java` → `Compiler`

- `Compiler compliance level` を **21** に設定

### 3.3 Gradle が使う JDK

`Window` → `Preferences` → `Gradle`

- `Java home` に JDK 21 のパスを指定する（未指定だと Eclipse 起動に使われた JRE が採用され、
  バージョン差でビルドが通らないことがある）

### 3.4 EditorConfig の適用（任意）

Eclipse は標準では `.editorconfig` を読まない。`Help` → `Eclipse Marketplace` から
**editorconfig-eclipse** を導入すると、インデント幅などが自動で揃う。
導入しない場合は、Java のインデントを 4 スペースに手動設定する
（`Preferences` → `Java` → `Code Style` → `Formatter`）。

## 4. Java プロジェクトの作成

**配置先は `src/backend/`**。以下の 2 通りのうち、方法 A を推奨する。
ディレクトリの位置を正確にコントロールできるため。

### 方法 A：Spring Initializr の ZIP を展開する（推奨）

1. https://start.spring.io/ を開き、次のとおり設定する

   | 項目 | 値 | 既定値からの変更 |
   | --- | --- | --- |
   | Project | **Gradle - Kotlin** | 要変更（既定は Gradle - Groovy） |
   | Language | Java | そのまま |
   | Spring Boot | **4.1.1** | そのまま（SNAPSHOT / M 版は選ばない） |
   | Group | `jp.co.sample` | 要変更 |
   | Artifact | `kintai` | 要変更 |
   | Package name | `jp.co.sample.kintai` | Artifact 変更時に自動で入る。要確認 |
   | Packaging | Jar | そのまま |
   | Configuration | **YAML** | 要変更（既定は Properties） |
   | Java | **21** | 要変更（既定は 17） |

2. `ADD DEPENDENCIES` から次の 7 つを追加する

   ```
   Spring Web
   Spring Data JPA
   Spring Security
   Validation
   Flyway Migration
   PostgreSQL Driver
   Spring Boot Actuator
   ```

   > **Lombok は追加しない。** Java 21 の `record` があれば getter・equals・hashCode は不要であり、
   > `@Data` はドメインオブジェクトを可変にする方向に働くため。理由は ADR に記録する。

> **Spring Boot のバージョンについて**
   > 3.5 系は OSS サポートが終了し、Initializr の選択肢から外れている。
   > 安定版は 4.1.1 と 4.0.8 の 2 つで、最新の安定版である **4.1.1** を採用する。
   > SNAPSHOT と M（マイルストーン）版は開発途上のため選ばない。

3. `GENERATE` で `kintai.zip` をダウンロードし、展開する

4. 展開してできた `kintai/` フォルダの **中身** を、クローンしたリポジトリの `src/backend/` へ移す

   ```
   newJavaProject/
   └── src/
       └── backend/
           ├── build.gradle.kts
           ├── settings.gradle.kts
           ├── gradlew
           ├── gradlew.bat
           ├── gradle/wrapper/
           └── src/main/java/jp/co/sample/kintai/KintaiApplication.java
   ```

   `src/backend/kintai/build.gradle.kts` のように **一段深くならないよう注意する**。
   Initializr が生成する ZIP は `kintai/` フォルダを含むため、その中身だけを移す。

5. Initializr が生成した `.gitignore` と `.gitattributes` は **削除する**

   リポジトリのルートに同等のものがあり、二重管理になるため。
   どちらを直せばよいか分からなくなる状態を避ける。

6. **macOS / Linux の場合のみ**、`gradlew` に実行権限を付ける

   ```bash
   chmod +x src/backend/gradlew
   ```

### 方法 B：Eclipse のウィザードを使う

Spring Tools 4 プラグインが必要（`Help` → `Eclipse Marketplace` で "Spring Tools 4" を検索）。

1. `File` → `New` → `Other...` → `Spring Boot` → `Spring Starter Project`
2. `Use default location` の **チェックを外し**、`Location` にクローンしたリポジトリの
   `src/backend` を指定する
3. それ以外の項目は方法 A の表と同じ値を入力する

> ウィザードが `src/backend/kintai/` のように一段深く作ってしまった場合は、
> 中身を `src/backend/` 直下へ移動してからインポートし直す。

## 5. Eclipse へのインポート

1. `File` → `Import...` → `Gradle` → `Existing Gradle Project` → `Next`
2. `Project root directory` に `<クローン先>/newJavaProject/src/backend` を指定
3. `Finish`

初回は Gradle が依存関係をダウンロードするため数分かかる。
`Gradle Tasks` ビュー（`Window` → `Show View` → `Other` → `Gradle`）にタスクが並べば成功。

### ビルドの確認

```bash
cd src/backend
./gradlew compileJava        # Windows は gradlew.bat compileJava
```

> **`build` ではなく `compileJava` で確認する。**
> `build` はテストを含み、`KintaiApplicationTests.contextLoads()` が
> データソースを要求する。データベースの接続設定を入れるまでは必ず失敗するため、
> この段階ではコンパイルが通ることだけを確認する。

## 6. データベースの起動

リポジトリのルートで実行する。

```bash
docker compose up -d
docker compose ps        # State が healthy になることを確認
```

| 項目 | 値 |
| --- | --- |
| ホスト / ポート | `localhost:5432` |
| データベース | `kintai` |
| ユーザー / パスワード | `kintai` / `kintai` |

停止は `docker compose down`。データも消す場合は `docker compose down -v`。

## 7. Git によるバージョン管理

### 7.1 Eclipse が生成するファイルについて

`.project` `.classpath` `.settings/` `bin/` は Eclipse が自動生成する環境依存のファイルで、
**すべて `.gitignore` 済み**のためコミットされない。他の IDE を使う人と衝突しないようにするため。

一方、以下は**必ずコミットする**。

| ファイル | 理由 |
| --- | --- |
| `gradlew` / `gradlew.bat` | Gradle 本体を入れていない環境でもビルドできるようにするため |
| `gradle/wrapper/gradle-wrapper.jar` | 同上。`.gitignore` で明示的に除外対象から外している |
| `gradle/wrapper/gradle-wrapper.properties` | Gradle のバージョンを固定するため |

**`gradlew` の実行権限に注意する。**
Windows でコミットすると実行権限のビットが落ち、macOS / Linux と GitHub Actions で
`Permission denied` になる。リポジトリのルートに `.gitattributes` を置いて改行コードは
統一しているが、パーミッションは Git の管理外なので、落ちた場合は次のコマンドで戻す。

```bash
git update-index --chmod=+x src/backend/gradlew
```

### 7.2 コマンドラインで操作する場合

```bash
# 何が追加されるか確認する（Eclipse の生成物が混ざっていないかを見る）
git status

# バックエンドのプロジェクトを追加
git add src/backend
git commit -m "バックエンドのプロジェクト雛形を追加"

# リモートへ反映
git push origin claude/java-personal-project-ideas-f08w42
```

Windows で `gradlew` の実行権限が落ちている場合は、コミット前に付与する。

```bash
git update-index --chmod=+x src/backend/gradlew
```

### 7.3 Eclipse（EGit）で操作する場合

Eclipse は EGit を同梱しているため、追加インストールは不要。

**リポジトリの登録**

1. `Window` → `Show View` → `Other...` → `Git` → `Git Repositories`
2. `Add an existing local Git repository` を選び、クローンしたフォルダを指定

`src/backend` は既存リポジトリの配下にあるため、Gradle プロジェクトをインポートすると
EGit が自動的に親の `.git` を検出して関連付ける。
関連付かない場合のみ、プロジェクトを右クリック → `Team` → `Share Project` → `Git` →
`Use or create repository in parent folder of project` にチェックを入れる。

> **新しいリポジトリを作らないこと。** `src/backend` の直下に `.git` を作ってしまうと
> リポジトリが入れ子になり、親からファイルが追跡できなくなる。

**コミットとプッシュ**

1. プロジェクトを右クリック → `Team` → `Commit`
2. `Git Staging` ビューで、`Unstaged Changes` から必要なファイルを `Staged Changes` へ移す
3. コミットメッセージを入力し、`Commit and Push...`

### 7.4 コミットメッセージの規約

- **1 行目に何をしたかを日本語で簡潔に書く**（体言止めまたは「〜を追加」「〜を修正」）
- 2 行目は空行
- 3 行目以降に、なぜそうしたかを書く。何をしたかは差分を見れば分かるが、理由は書かないと残らない

```
フレックスタイム制の月次清算ロジックを追加

日々8時間を超えても時間外にならないため、固定時間制とは判定の
タイミングが異なる。清算期間の総枠計算を独立した規則として実装し、
BR-05 のテストケースで仕様を固定した。
```

### 7.5 共同作業時の同期

このリポジトリは複数の環境（ローカルの Eclipse と、リモートの開発セッション）から
更新される。作業を始める前に必ず最新を取り込む。

```bash
git pull origin claude/java-personal-project-ideas-f08w42
```

Eclipse では プロジェクト右クリック → `Team` → `Pull`。

> **履歴の書き換え（force push）は行わない。** 一方が履歴を書き換えると、
> もう一方のローカルリポジトリと辻褄が合わなくなるため。

## 8. よくあるトラブル

| 症状 | 原因と対処 |
| --- | --- |
| Eclipse で日本語が文字化けする | `Preferences` → `General` → `Workspace` → `Text file encoding` が UTF-8 になっていない。設定後、既に壊れたファイルは Git から復元する |
| `gradlew: Permission denied` | 実行権限が無い。`chmod +x src/backend/gradlew` |
| Gradle のビルドが Java のバージョンで失敗する | `Preferences` → `Gradle` → `Java home` が JDK 21 を指しているか確認する |
| `docker compose up` でポート競合 | ローカルの PostgreSQL が 5432 を使用している。既存のものを停止するか、`docker-compose.yml` のポートを変更する |
| `.settings/` などが `git status` に出る | `.gitignore` が効いていない。すでに追跡済みの場合は `git rm -r --cached <path>` で追跡から外す |
