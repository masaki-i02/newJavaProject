# バックアップとリストア

| 項目 | 内容 |
| --- | --- |
| 文書番号 | KNT-OPS-002 |
| 版 | 0.1 |
| 最終更新 | 2026-09-07 |

## なぜ要るか

要件定義書 7 は「労働関係の記録として **5 年間保持する**」と定めている。
これは法令に由来する要求（労基法 109 条）なので、
「個人開発だから SLA は定義しない」という理由では降ろせない。

**5 年保持を要件に書きながら保持の手段が無い状態が、いちばん悪い。**

## 目標

| 項目 | 値 | 理由 |
| --- | --- | --- |
| RPO（どこまで失ってよいか） | **24 時間** | 打刻は翌日に本人が訂正申請で直せる（BR-09）。1 日ぶんなら業務で回復できる |
| RTO（どれだけで戻すか） | **1 時間** | 打刻できない時間が 1 日を超えると、その日の一次証拠が失われる |
| 保持 | **日次 14 世代 + 月次 60 世代** | 月次 60 世代で 5 年になる |

**決めて書くことに意味がある。** 決めないと、
「どこまで失ってよいか」を事故のあとに決めることになる。

## 取り方

`docker-compose.prod.yml` は `./backup` を db コンテナの `/backup` に結びつけてある。

```bash
#!/bin/sh
# scripts/backup.sh — cron から毎日 1 回
set -eu
: "${KINTAI_DB_USER:?}" "${KINTAI_DB_NAME:?}"
stamp=$(date +%Y%m%d)

# ★ -Fc（カスタム形式）にする。pg_restore で表を選んで戻せる。
#   平文の SQL だと、1 つの表だけを戻したいときに手で切り出すことになる
docker compose -f docker-compose.prod.yml exec -T db \
  pg_dump -U "$KINTAI_DB_USER" -d "$KINTAI_DB_NAME" -Fc \
  > "backup/kintai-${stamp}.dump"

# 日次は 14 世代。月初のものは別に残す（月次 60 世代）
find backup -name 'kintai-*.dump' -mtime +14 \
     ! -name 'kintai-??????01.dump' -delete
```

```cron
# 毎日 3:00。年休の付与バッチ（2:30）より後に取る
0 3 * * * cd /srv/kintai && ./scripts/backup.sh >> /var/log/kintai-backup.log 2>&1
```

**バックアップの置き場をホストのディスクだけにしない。**
ディスクが壊れたら DB と一緒に失われる。別の場所へ複製する。

## 戻し方

```bash
# 1. アプリを止める。動いたまま戻すと、戻した直後の書き込みが混ざる
docker compose -f docker-compose.prod.yml stop app

# 2. 空のデータベースを作り直す
docker compose -f docker-compose.prod.yml exec -T db \
  psql -U "$KINTAI_DB_USER" -d postgres \
  -c "DROP DATABASE IF EXISTS $KINTAI_DB_NAME;" \
  -c "CREATE DATABASE $KINTAI_DB_NAME OWNER $KINTAI_DB_USER;"

# 3. 戻す
docker compose -f docker-compose.prod.yml exec -T db \
  pg_restore -U "$KINTAI_DB_USER" -d "$KINTAI_DB_NAME" --no-owner \
  < backup/kintai-20260907.dump

# 4. アプリを起動する。Flyway は validate だけを行う（スキーマは戻っている）
docker compose -f docker-compose.prod.yml start app
curl -fsS http://localhost:8080/actuator/health
```

### 戻したあとに確かめること

**「エラーが出なかった」で終わらせない。** 実際に値を見る。

| 確かめること | 見かた |
| --- | --- |
| 締め済みの月次勤怠が残っている | `SELECT count(*) FROM monthly_attendances WHERE status = 'CLOSED';` |
| 打刻が残っている（パーティションごと） | `SELECT count(*) FROM time_clock_events;` |
| Flyway の適用履歴が壊れていない | 起動が成功すれば `validate-on-migrate` が通っている |
| ログインできる | 画面から 1 回 |

## 実測値

**まだ測っていない。**
この環境ではコンテナレジストリへ到達できずコンテナを起動できないため、
初回構築のときに 1 回通して、下の表を埋めること。

| 項目 | 実測 | 測った日 |
| --- | --- | --- |
| バックアップの所要時間 | 未測定 | — |
| ダンプの大きさ | 未測定 | — |
| リストアの所要時間 | 未測定 | — |

**手順が書いてあるだけのバックアップは、無いのとほとんど変わらない。**
1 回戻すまでは「バックアップがある」と言わない。
