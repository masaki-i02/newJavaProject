## 1. エンドポイント一覧

| メソッド | パス | 概要 | 必要ロール |
| --- | --- | --- | --- |
| `POST` | `/api/payroll/exports` | 給与連携データを作り、記録を残す | `HR` |
| `GET` | `/api/payroll/exports/{id}` | 作った内容を CSV で受け取る | `HR` |
| `GET` | `/api/payroll/exports` | 出力の記録を照会する（監査） | `HR` |
| `GET` | `/api/payroll/scheduled-hours/{fiscalYear}` | 年間の所定と 1 か月平均所定労働時間数 | `HR` |

**すべて `HR` に限る。**
全社員の賃金の基礎になるデータであり、閲覧範囲を持つ一般社員・上長には開かない。
[06 API設計書 1](../06_年次有給休暇/API設計書.md) が「一覧を返す API をロールで一律に拒まない」と
書いているのは、**閲覧範囲で絞れば本人のぶんだけが返る**からである。
ここは本人のぶんを返す API ではないので、その理由が当てはまらない。

**依頼者は `shared.domain.Requester` を引数で渡す**（CLAUDE.md「依頼者の受け渡し」）。
`exported_by` はその `Requester` の社員 ID である。
`SecurityContextHolder` を `application` 層から読まない（落とし穴 42）。

### 1.1 このコンテキストのエラー型

| `type` | HTTP | 発生条件 |
| --- | --- | --- |
| `urn:kintai:error:validation-failed` | 400 | 月・年度の形式が不正（共通仕様 1.3）|
| `urn:kintai:error:forbidden` | 403 | `HR` ロールが無い |
| `urn:kintai:error:payroll-export-not-found` | 404 | その記録が無い |
| `urn:kintai:error:month-not-finished` | **409** | 対象月の末日が到来していない |
| `urn:kintai:error:calendar-not-registered` | 422 | 対象年度の会社カレンダーに未登録の日がある |
| `urn:kintai:error:calendar-exceeds-statutory-year` | 422 | 年間の所定が法定の総枠を超えている（労基法 32 条）|
| `urn:kintai:error:multiple-scheduled-working-times` | 422 | **同じ日**に所定の異なる就業規則が並んでいる |
| `urn:kintai:error:work-rule-not-in-use` | 422 | 対象年度に適用されている就業規則が 1 件も無い |
| `urn:kintai:error:no-scheduled-workday` | 422 | 対象年度に所定労働日が 1 日も無い（分母が 0 になる）|
| `urn:kintai:error:work-rule-not-applied-on` | 422 | 所定労働日なのに就業規則が誰にも適用されていない日がある |
| `urn:kintai:error:work-rule-version-missing` | 422 | **適用されているのに**版が無い日がある |

**`month-not-finished` は 05 と同じ型・同じ HTTP を使う。**
[05 API設計書 1.2](../05_申請承認と締め/API設計書.md) が `409` と定めており、
実装（`MonthNotFinishedException`）も `DomainErrorKind.CONFLICT` を返す。
同じ業務ルールがコンテキストごとに違う HTTP を返してはならない（落とし穴 110）。

**形式の不正に独自の型を作らない。** 共通仕様 1.3 の `validation-failed`（400）を使う。

**`work-rule-not-applied-on` と `work-rule-version-missing` を分ける。**
前者は「その日はまだ誰もその規則を使っていない」、
後者は「使っているのに版が無い」である。
一緒にすると、年度の途中で新設した系列を隙間と誤診断したまま
**その年度のどの月も出力できない**状態に戻る（落とし穴 131）。

### 1.2 CSV と除外一覧に社員番号を載せる

[設計規約チェックリスト 3](../00_共通/設計規約チェックリスト.md) は
「他コンテキストが所有する概念を返さない」と定めるが、
**`payroll` の目的そのものが「社員番号で名寄せできる 1 行を作ること」**である
（[ADR 0007](../../05_ADR/0007_給与連携を新しい業務コンテキストにする.md)）。

| 応答 | 社員番号 | 理由 |
| --- | --- | --- |
| CSV（§3） | **載せる** | 給与側の名寄せの鍵。これが無いと出力の意味が無い |
| 除外した社員（§2） | **載せる** | 人事が「誰を締めればよいか」を直接読む。UUID では行動できない |
| 出力の記録の照会（§4） | **載せない** | 実行者が誰かは画面の関心であり、`employee` から引けばよい |

**線は「給与処理の対象として必要か」で引く。**
規約の例外をコンテキストごとに書かないと、
「どちらでもよい」に退化する（落とし穴 18）。

## 2. `POST /api/payroll/exports`

![出力の流れ](images/出力の流れ.png)

<sub>図のソース: [`diagrams/出力の流れ.mmd`](diagrams/出力の流れ.mmd)</sub>

```json
{ "month": "2026-05" }
```

```json
{
  "exportId": "0195c000-0000-7000-8000-000000000010",
  "month": "2026-05",
  "exportedAt": "2026-06-10T09:12:44",
  "monthlyAverageMinutes": 9800,
  "rowCount": 97,
  "excluded": [
    { "employeeNumber": "E0042", "reason": "NOT_APPROVED" },
    { "employeeNumber": "E0088", "reason": "NO_ATTENDANCE_RECORD" }
  ]
}
```

| 応答 | 条件 |
| --- | --- |
| `201 Created` | 記録を作った。`Location` に `GET` の URL |
| `403 forbidden` | `HR` ロールが無い |
| `409 month-not-finished` | **対象月がまだ終わっていない** |
| `422 calendar-not-registered` | 対象月が属する年度のカレンダーが登録されていない |
| `400 validation-failed` | 月の形式が不正 |

### 2.1 対象月が終わっていない依頼は例外にする

**社員ごとの事情は結果へ、依頼そのものの不備は例外へ**（落とし穴 60）。

| 何が起きたか | どう返すか | 理由 |
| --- | --- | --- |
| 一部の社員が未締め | `excluded` に入れて `201` | 依頼は正当。全件を止めると 1 人の未締めで給与処理が止まる |
| **全員が未締め** | `excluded` に全員を入れて `201` | 同じ理由。`rowCount` が 0 になるだけで、依頼の不備ではない |
| 対象月がまだ終わっていない | `409` | 締められるはずがない。結果にすると、人事は**まだ出せる月だと誤解する** |
| 年度のカレンダーが未登録 | `422` | 1 か月平均所定労働時間数を記録できない。**365 日で計算した値を静かに残してはならない**（ドメインモデル設計書 4）|

> **「全員が未締め」を例外にしない。**
> 例外にすると、締め忘れが 1 人でもいる月と、そもそも誰も締めていない月とで
> 応答の形が変わる。人事が見たいのは**どちらの場合も「誰が残っているか」**である。

### 2.2 除外の理由

| `reason` | 意味 |
| --- | --- |
| `NOT_SUBMITTED` | 打刻はあるが下書きのまま |
| `NOT_APPROVED` | 提出済み・未承認 |
| `NOT_CLOSED` | 承認済み・未締め |
| `NOT_SUBMITTABLE` | 提出の事前条件を満たしていない（未退勤・就業規則が未適用）|
| `NO_ATTENDANCE_RECORD` | **その月の打刻が 1 件も無い** |
| `DUPLICATE_EMPLOYEE_NUMBER` | 同じ社員番号の社員が対象月に 2 人いる |

判定の根拠はドメインモデル設計書 3.2。
**`NO_ATTENDANCE_RECORD` を「月次勤怠の行が無いこと」で判定しない。**
行が無いことは「下書き」を意味するので、
1 か月働いて提出していないだけの社員に打刻漏れを疑わせることになる。

`excluded` は**空でも項目ごと省かない。**
`warnings` と違い、`excluded: []` は「全員が締まっている」という積極的な意味を持つ
（[05 API設計書 2.2](../05_申請承認と締め/API設計書.md) の `warnings` とは扱いが逆である）。

## 3. `GET /api/payroll/exports/{id}`

`Accept: text/csv`。本文は CSV。

```
社員番号,対象月,清算期間開始,清算期間終了,労働時間制度,暦月所定労働日数,清算期間所定労働日数,出勤日数,年休日数,欠勤日数,実労働,所定内,所定超,法定外残業60hまで,法定外残業60h超,法定休日,深夜,所定総,不足
E0001,2026-05,2026-05-01,2026-05-31,FIXED,20,20,20,0,0,9600,9600,0,0,0,0,0,9600,0
E0002,2026-05,2026-05-18,2026-05-31,FLEX,20,10,10,0,0,4800,4800,0,0,0,0,0,4800,0
```

| 決定 | 理由 |
| --- | --- |
| **文字コードは UTF-8（BOM 付き）** | 氏名を出さないので非 ASCII はヘッダ行だけだが、BOM が無いと Excel が Shift_JIS と解釈して見出しが化ける |
| **改行は CRLF** | RFC 4180。給与ソフトの取込で最も通る |
| **時間は分（整数）** | 1 分単位で丸めない（BR-01）。`H:MM` にすると受け手が再び分へ戻すことになり、そこで丸めが混入する |
| **日数は整数** | 年休は 1 日単位（BR-16）|
| **清算期間の終了日は閉区間の最終日** | CSV は人が読む。半開区間の `2026-06-01` を「5 月の終わり」として渡すと必ず取り違える（落とし穴 10・112）|
| **所定労働日数を 2 列に分ける** | 日額（月給 ÷ これ）の分母は**暦月**、所定総の根拠は**清算期間**である。E0002（5/18 入社）の行では 20 日と 10 日に分かれる。清算期間のほうを分母に使うと控除が 2 倍になる（労基法 24 条）。しかも暦月の所定労働日数は他のどの列からも復元できない |
| **清算期間開始・終了は賃金計算期間ではない** | 賃金計算期間（労基則 54 条 1 項 3 号）は賃金規程が定めるもので、月末締めでは②の暦月である。③は在籍期間で切ってある |
| **社員番号 → 入社日の昇順で並べる** | 順序が安定していないと、同じ月の CSV の差分が取れない。番号は再利用されうるので、番号だけでは一意に決まらない。**並べるのは `application` / `presentation` である**（永続化アダプタが `employees` を JOIN すると、ArchUnit が見ない SQL の中に `payroll → employee` の辺が生まれる）|
| ヘッダ行を付ける | 列の追加に耐える。位置だけで読ませると、列を足した瞬間に取込が壊れる |
| **所定内と所定超を隣に置く** | 足すと実労働になる。給与側が「どちらに 1.0 倍を払うか」を列の並びで読める |

| 応答 | 条件 |
| --- | --- |
| `200 OK` | `text/csv; charset=utf-8` |
| `403 forbidden` | `HR` ロールが無い |
| `404 payroll-export-not-found` | その記録が無い |

### 3.1 同じ id からは必ず同じ内容が返る

CSV の本文は**保存していない**。
記録に残した**対象社員**（`payroll_export_targets`）を読み、
その社員の締め済みの月次清算から作り直す。

**行の値が動かないことと、行の集合が動かないことは別である。**
対象社員を記録していないと、`POST` のあとに人事が残りの社員を締めたとき、
同じ `id` から取得した CSV の行数が増える。
記録の `rowCount` と食い違い、**記録が「何を出したか」を指さなくなる**
（ドメインモデル設計書 5.1）。

> **IT-PAY-38 は、取得の間に締めを挟んで確かめる。**
> 挟まないケースだけを書くと、集合を固定していない実装でも通る（落とし穴 24・43）。

## 4. `GET /api/payroll/exports`

出力の記録を照会する（監査）。

| クエリパラメータ | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `month` | `YYYY-MM` | — | 対象月で絞る |
| `limit` | 整数 | — | 既定 20・最大 100 |

```json
{
  "exports": [
    { "exportId": "...", "month": "2026-05",
      "exportedBy": "0195c000-0000-7000-8000-000000000001",
      "exportedAt": "2026-06-10T09:12:44",
      "monthlyAverageMinutes": 9800,
      "rowCount": 97, "excludedCount": 3 }
  ]
}
```

**`exportedAt` の降順で返す。** 監査は「最後に出したのはいつか」から見る。

**実行者の社員番号・氏名を返さない**（1.2 の線引き）。
画面は `GET /api/employees?ids=...` で引く。

`rowCount` / `excludedCount` は `payroll_export_targets` から数える。
**列としては持たない**（DB設計書 1 の 4）。

## 5. `GET /api/payroll/scheduled-hours/{fiscalYear}`

```json
{
  "fiscalYear": 2026,
  "period": { "from": "2026-04-01", "toExclusive": "2027-04-01" },
  "scheduledDays": 245,
  "monthlyAverageMinutes": 9800
}
```

| 決定 | 理由 |
| --- | --- |
| 年度は 4 月 〜 翌 3 月 | 36 協定の年度（BR-12）とそろえる |
| 社員を指定しない | 会社の所定であり、全社員に共通である（労基則 19 条 1 項 4 号）|
| 年休を差し引かない | 社員ごとの事情であり、基礎額は会社の所定で決まる |
| `period` を返す | 「年度」の解釈は会社によって違う。どの範囲で数えたかを示す |
| **カレンダー未登録の年度は 422** | 未登録の日は所定労働日として扱われるので、年間 365 日・月平均 243 時間 20 分になり、**割増の単価が法定を約 33% 下回る**。静かに返してはならない（ドメインモデル設計書 4）|

| 応答 | 条件 |
| --- | --- |
| `200 OK` | — |
| `403 forbidden` | `HR` ロールが無い |
| `422 calendar-not-registered` | その年度に未登録の日が 1 日でもある（「法定休日が 1 日も無い」では 4 月だけ登録した年度がすり抜ける） |

## 7. 実装上の注意

| # | 内容 |
| --- | --- |
| 1 | 月次清算・日数・状態を**社員ごとに問い合わせない。** 100 名ぶんで N+1 になる。対象月ぶんをまとめて読む経路を新設する（ドメインモデル設計書 6）|
| 2 | 締め状態は `approval` の `application` に問う。**`MonthClosureQuery` は使わない。** 除外理由を状態で分けるには状態そのものが要り、`isClosed` では足りない。`MonthClosureQuery` は `approval` へ直接依存できないコンテキストのためのポートであり、`payroll → approval` の辺を持つ `payroll` には当てはまらない |
| 3 | 所定労働日数・出勤日数・欠勤日数は `attendance` に問う。`payroll` が会社カレンダーを引いて数え直さない（落とし穴 67）|
| 4 | ⑩⑪は `MonthlySettlement` の導出メソッドを呼ぶ。`payroll` に式を置かない |
| 5 | CSV の組み立ては `presentation`。`application` は `PayrollRow` のリストを返すところまで |
| 6 | `exported_at` は DB の `now()`。アプリケーションから渡さない |
| 7 | 1 日の所定労働時間を定数で書かない。`workrule` の就業規則から読む（落とし穴 15・67）|
