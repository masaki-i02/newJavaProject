# 02_詳細設計

要件定義書（KNT-REQ-001）を、実装可能な粒度まで具体化した文書を置く。

## 作成予定の文書

| 文書 | 内容 | 状態 |
| --- | --- | --- |
| [アーキテクチャ設計書](アーキテクチャ設計書.md) | レイヤ構成、依存の方向、パッケージ構成、採用技術とその選定理由 | 作成済 |
| ドメインモデル設計書 | クラス図、値オブジェクトと集約の境界、状態遷移図 | 未着手 |
| DB設計書 | ER 図、テーブル定義、制約一覧、インデックス設計、パーティション方針 | 未着手 |
| API設計書 | エンドポイント一覧、リクエスト／レスポンス定義、エラー応答 | 未着手 |
| 画面設計書 | 画面一覧、画面遷移図、各画面の項目定義 | 未着手 |

## 方針

- **DB 設計書には「なぜその制約を置いたか」を必ず書く。** 制約一覧が単なるカラムの羅列に
  なると、後から読んでも設計意図が分からなくなる。
- ER 図とクラス図は Mermaid で記述し、Markdown 内に埋め込む。画像ファイルにすると
  差分が追えなくなるため。
