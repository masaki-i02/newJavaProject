# 02_詳細設計

要件定義書（KNT-REQ-001）を、実装可能な粒度まで具体化した文書を置く。

**業務コンテキスト単位に細分化する。** 1 つの巨大な設計書にすると、
どこを直せばよいか分からなくなり、レビューもしづらくなるため。
コンテキストの分割は [ADR 0001](../05_ADR/0001_パッケージを業務コンテキスト優先で分割する.md) に従う。

## 構成

| フォルダ | 対象 | 実装先パッケージ | 状態 |

## 各フォルダの構成

```
01_社員・組織/
├── ドメインモデル設計書.md
├── DB設計書.md
├── API設計書.md
├── diagrams/            図のソース（Mermaid）
│   └── ドメインモデル.mmd
└── images/              生成された PNG
    └── ドメインモデル.png
```

## 方針

- **図は PNG を成果物とする。** Markdown を開いた瞬間に図が見える状態を保つ。
  ソースの `.mmd` も併せてコミットし、差分を追えるようにする。
  生成方法は [_tools/README.md](../_tools/README.md) を参照
- **DB 設計書には「なぜその制約を置いたか」を必ず書く。**
  制約一覧が単なるカラムの羅列になると、後から読んでも設計意図が分からなくなる
- **要件定義書の業務ルール ID（BR-xx）を必ず参照する。**
  設計のどの部分がどの要件に由来するかを辿れるようにする
